# CorPath

**Core Path · 核心之路** —— 个人博客，记录人生之路与开发之路的思考。

人生之路：旨在探求与追寻人生的幸福、价值与意义，比如世界观、人生观、道德观、历史观、幸福观等等。

开发之路：注重人生的实现，旨在开发人生，包括技术能力、处世方式、职业、工作、生活、生存等等。

站点地址：<https://corpath.github.io>

## 设计理念

这套博客系统本质上是**把电脑里的「文件系统 / 资源管理器」搬到了网页上**，由两条相互正交的轴构成：

- **纵向：一棵可以无限嵌套的目录树。** 最顶层是「人生之路」和「开发之路」两个根文件夹；每个文件夹里既能放文章（文件），也能放子文件夹（子目录），子文件夹里还能继续放——理论上没有层级上限。文件夹本身就是 URL 路径，访问 `/dev/` 就是打开 `dev/index.html`。
- **横向：一套横切整棵树的标签索引。** 标签不属于任何文件夹，而是全局的。一篇文章「住」在唯一的文件夹里，但可以挂任意多个标签；点某个标签，会把散落在任意层级、任意顶层目录下的所有同类文章聚合到一起。**目录决定文章在哪，标签决定文章怎么被找到——两者互不干扰。**
- **目录页里，文件和文件夹一视同仁。** 打开任一文件夹，文章与子文件夹混在同一个列表中、用相同样式并排列出；区别只在点击行为——点文章是阅读，点文件夹是进入下一级目录。这正是资源管理器里「文件和文件夹同级」的观感。
- **单一数据源 + 自动渲染。** 上面这一切都由 `assets/posts.js` 这一份数据驱动，页面加载时脚本现场生成列表，不手写、不多处同步。

## 结构

采用「顶层两大板块 → 子文件夹 → 文章」的层级结构，像电脑里的文件夹一样可无限嵌套。文件夹即 URL 路径。**目录列表是自动渲染的**：所有页面都从 `assets/posts.js` 这一份数据读取内容，不用手写列表。

```
.
├── index.html                  首页：岔路口门户 + 阴阳双鱼图（卡片列表自动生成）
├── about.html                  关于：CorPath 名字的由来 + 阴阳双鱼图
├── tags.html                   标签索引页：跨两条路按标签聚合文章
├── assets/
│   ├── style.css               全站统一样式（黑 / 白 / 浅灰为底 + 低饱和双色点缀）
│   ├── posts.js                站点数据：目录树 + 标签清单（唯一数据源）
│   ├── dir.js                  目录页 / 首页渲染脚本（读 posts.js 自动生成列表）
│   ├── tags.js                 标签页逻辑（读 posts.js 渲染标签云与筛选结果）
│   └── taiji.svg               黑白阴阳双鱼图（内置缓慢旋转动画）
├── life/                       人生之路 · Life
│   └── index.html              目录页（列表由 dir.js 生成）
└── dev/                        开发之路 · Dev
    ├── index.html              目录页（列表由 dir.js 生成）
    └── 2026-11-17-....html     文章
```

## 设计约定

- **顶层当前有两个板块**：`life/`（人生之路）与 `dev/`（开发之路）。技术上不限数量，新增顶层的方法见后文「如何新增顶层主文件夹」——但要注意界面上有几处是按「两条路」设计的，需要同步扩展。
- **每个文件夹都是一个板块**：文件夹内可继续放子文件夹（子板块）和文章，形成层级。
- **每个文件夹必须有一个 `index.html`**：它是该文件夹的目录页。GitHub Pages 访问 `/some-folder/` 时会寻找其中的 `index.html`，缺失则该路径 404。
- **文件夹与文章同级展示**：打开任一目录页，`dir.js` 会把该文件夹里的文章和子文件夹混在同一个列表中、用相同样式呈现；点文章是阅读，点文件夹是进入下一级目录。
- **文章是时间流**：目录内的文章按 `date` 倒序（最新在前）由脚本排列。
- **视觉分工**：整体以黑、白、浅灰为底；人生之路用低饱和暖赭（terracotta），开发之路用低饱和墨青（teal）做克制点缀，一暖一冷呼应阴阳双鱼；首页以「岔路口」呈现两条路径。

## 数据是怎么驱动的

`assets/posts.js` 里有一棵 `window.CORPATH_TREE`：`children` 是顶层文件夹列表（当前是 life、dev 两个，数量不限），每个文件夹的 `children` 里可以混放两类节点——

- `kind:"post"` 文章：`date` / `title` / `file`（该文件夹内的文件名）/ `excerpt` / `tags`
- `kind:"folder"` 子文件夹：`key`（实际目录名）/ `title` / `desc` / `children`（可继续嵌套）

页面加载时：

- `dir.js` 读取 `data-dir`（如 `dev` 或多级路径 `dev/subfolder`）找到对应文件夹，自动生成标题、面包屑和列表；首页的两张卡片也从这里取近期文章。
- 同一份数据被 `posts.js` 自动「扁平化」成 `window.CORPATH_POSTS`，供 `tags.js` 使用，所以标签天然跨目录、跨两条路。

**结论：新增文章或子文件夹，正文内容和列表都只在一处维护——`posts.js`。**

## 如何新增一篇文章

1. 在对应文件夹里新建 HTML 文件，命名 `YYYY-MM-DD-标题.html`（如 `2026-11-20-读某某书.html`）。
2. 在 `assets/posts.js` 对应文件夹的 `children` 里加一条 `kind:"post"` 记录（title / date / file / excerpt / tags）。
3. 目录列表与首页卡片会自动更新，无需改任何 `index.html`。

## 如何新增一个子文件夹（子板块）

1. 建文件夹，复制任一个 `index.html` 进去，把 `<body>` 的 `data-dir` 改成新路径（如 `dev/newfolder`）。注意相对层级：`../../assets/` 还是 `../../../assets/`。
2. 在 `posts.js` 对应位置加一条 `kind:"folder"` 记录（`key` 必须和真实目录名一致），里面放它的 `children`。
3. 上一层目录页会自动把这个文件夹作为一个条目列出来，访客点得到，不用手动加链接。

## 如何新增顶层主文件夹（第 3 条、第 4 条路）

**数据层天然支持，但界面层有几处按「两条路」写死，需要同步改。** 别以为只加一条数据就完事——按下面清单走：

1. **加数据节点**：在 `posts.js` 的 `tree.children` 里加一个顶层文件夹（`key` / `dir` 用新目录名，`title` / `kicker` / `desc` / `theme` 填好，`children` 里放文章或子文件夹）。加完即可获得：自动生成的目录页（前提见第 2 步）、文章自动进入标签系统。
2. **建目录与目录页**：建真实文件夹，里面放一个 `index.html`，`<body>` 的 `data-dir` 设为新顶层名（如 `book`），相对路径用 `../assets/`（顶层目录只下一层）。
3. **⚠️ 改 `dir.js` 的主题判断**：目前第 35 行写死 `top === "life" ? "life" : "dev"`，新顶层会被当成 dev 的墨青色。要扩展成按 `top` 映射到对应 `theme`，并在 `style.css` 补一套该主题的配色变量与 `.board-head.<theme>` 等样式。
4. **⚠️ 改首页**：`index.html` 只有两张 `.path-card`，`dir.js` 第 150 行也写死了 `[["life", …], ["dev", …]]`。要让新主文件夹上首页，得加卡片容器并扩展这段渲染逻辑。首页「岔路口 + 阴阳双鱼 + 殊途同归本就是同一条」的文案本身也是围绕两条路写的，加第三条路后建议重写叙事。
5. **⚠️ 改 `tags.js` 的徽章判断**：第 86 行写死 `isLife = p.path === "life"`，非 life 一律显示「开发之路」。新顶层会被错误标注，要改成按 `path` 映射到真实标题。
6. **改导航**：每个 HTML 的 `<nav class="site-nav">` 是手写的，新顶层要手动加一个链接。

> 一句话：**「目录树 + 标签索引」这套机制是通用的、无限可扩展的；但「两条路」的外壳（首页双卡、导航、标签徽章、阴阳叙事）是按 2 设计的**，加第 3、第 4 条路时这些外壳要一起扩展。如果你打算真的加，我可以把这些硬编码改成数据驱动，让新增顶层也变成「只改数据」。

## 标签系统（跨两条路打通）

标签不依赖任何后台或数据库，全部以代码维护。标签页读的是 `posts.js` 自动扁平化出来的 `window.CORPATH_POSTS`，而不是目录树本身——所以标签和目录是两套正交的视角：

- **文章藏在任何层级都能被检索**：无论文章在顶层还是深层子文件夹，扁平化时会自动算出它的完整 `url`，标签页都能正确打开。
- **两条路共用同一套标签**：`life` 和 `dev` 的文章可以打同一个标签；打开 `tags.html` 点该标签，两条路中带此标签的文章会一起显示。
- **新增标签**：无需改 HTML，只要在 `posts.js` 某篇文章的 `tags` 数组里写入新标签文字，标签云会自动出现它。
- **URL 直达筛选**：`tags.html?tag=标签名`（中文需 URL 编码）。文章页、目录页的标签徽章已做成这样的链接。
- 标签页不传参数时按日期倒序列出全部文章。

> 新增文章只要在 `posts.js` 的树里登记一次，目录页、首页卡片、标签系统三处会同时生效。

## 阴阳双鱼图

`assets/taiji.svg` 是首页与关于页共用的阴阳双鱼图：**黑底白鱼（鱼眼互含黑白）**，内置缓慢旋转动画，呼应整体的黑白灰基调。鱼背后的暖冷双色光晕、以及两条路各自的暖赭 / 墨青点缀，是在 `style.css` 里实现的。想调整图本身只改这一个文件，两处页面同步生效。

## 本地预览

纯静态站点，无需构建工具。直接双击 `index.html` 用浏览器打开即可；或在仓库根目录起一个静态服务器：

```bash
python -m http.server 8000
# 浏览器访问 http://localhost:8000
```

## 部署

推送到 GitHub 后，在仓库 **Settings → Pages** 中：

- Source 选择 **Deploy from a branch**
- 分支选 `main`，目录选 `/ (root)`，保存

等待约 1–2 分钟构建完成，访问 `https://corpath.github.io`。每次 push 后需等待重新构建，浏览器可用 `Ctrl+F5` 强制刷新以避开缓存。

**推送后能不能看？** 能。GitHub Pages 把仓库里的静态文件发布成公开网站，只要设备能访问 `corpath.github.io` 这个域名——**手机、平板、电脑用各自浏览器打开同一个网址即可**，不需要装任何东西，也不要求访客有 GitHub 账号。你更新内容的方式仍是本地改文件 → `git commit` → `git push`，推送后等 1–2 分钟自动更新。

## 手机端显示

站点是响应式（responsive）的，做了这些移动端适配：

- 每个页面都有 `<meta name="viewport" content="width=device-width, initial-scale=1.0">`，保证按设备宽度正确排版、不被缩放。
- `style.css` 里有 `@media (max-width: 640px)` 规则：窄屏时首页两张路卡片由并排改为**上下堆叠**、标题字号缩小、太极图缩小、导航间距收紧。
- 布局用弹性盒（`flex`）与相对宽度，目录列表、标签云会自动换行；表格宽度 100% 自适应。

因此主流手机浏览器（Safari / Chrome / 微信内置浏览器）都能正常阅读。注意：目前是**按 CSS 规则做的适配，尚未在真实手机上逐一实测**；如果你在手机上发现某处挤或错位，告诉我具体页面和机型，我再针对性调整。
